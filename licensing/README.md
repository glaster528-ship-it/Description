# License Gate

отдельный сервис проверки лицензии по ключу и переданному HWID: Express API, SQLite и веб-экран входа на русском. исходный архив HwidLab не изменён; модуль не подключён к его драйверам, лоадеру или операциям изменения идентификаторов. очистки системных журналов и Prefetch, сборки драйверов и Inno Setup здесь нет.

## запуск

нужен Node.js 24.x и npm. зависимости закреплены в `package-lock.json`, дополнительных серверов баз данных нет.

```sh
cd licensing
npm ci --ignore-scripts
npm run configure
npm run --silent license -- issue --days 30
npm start
```

откройте `http://127.0.0.1:3000`. команда выдачи печатает JSON с `id`, `key` и `expiresAt`; сохраните ключ в защищённом месте и передайте владельцу лицензии. повторно получить исходный ключ из базы нельзя. не направляйте вывод этой команды в общий журнал.

`configure` создаёт `.env` с криптографически случайным секретом, не выводит его и не перезаписывает существующий файл. `.env`, база и `node_modules` исключены из Git и поставляемого архива.

на форме введите выданный ключ и стабильный HWID. браузер не получает аппаратные идентификаторы: значение передаётся пользователем либо отдельным клиентом. HWID чувствителен к регистру, имеет длину 16–128 символов и допускает латиницу, цифры, `.`, `_`, `:` и `-`.

## поведение лицензии

- первая успешная активация атомарно привязывает ключ к одному HWID;
- другой HWID отклоняется, пока администратор не сбросит привязку;
- сервер проверяет срок, отзыв и привязку при каждом запросе состояния сессии;
- повторная активация заменяет предыдущую сессию этой лицензии;
- сессия живёт не более 15 минут и никогда не дольше лицензии;
- выход удаляет сессию, но сохраняет привязку устройства;
- сброс привязки и отзыв лицензии завершают существующую сессию.

при неверном ключе, другом HWID, отзыве и истечении срока API возвращает одинаковую ошибку. ключи, HWID и токены сессий хранятся только как HMAC-SHA256 с разделёнными доменами. клиент получает непрозрачную HttpOnly cookie, а не секрет подписи или JWT. ключ не помещается в URL, браузерное хранилище или журналы запросов.

## администрирование

HTTP-эндпоинтов администратора нет. команды запускаются локально с доступом к той же `.env` и базе:

| команда | результат |
| --- | --- |
| `npm run --silent license -- issue --days 30` | новая лицензия; число дней — целое от 1 до 3650 |
| `npm run --silent license -- list` | список идентификаторов и статусов, без ключей и HWID |
| `npm run --silent license -- revoke --id ID` | отзыв лицензии и удаление её сессии |
| `npm run --silent license -- reset-device --id ID` | сброс привязки и удаление её сессии |

вместо `ID` скопируйте поле `id` из результата выдачи или списка. ключ не передаётся аргументом команды, где его могли бы увидеть средства просмотра процессов.

## API

веб-клиент обслуживается тем же Express-приложением, CORS не включён. для POST обязателен `Content-Type: application/json`, размер тела ограничен 2 КиБ. неизвестные поля отклоняются.

| метод и путь | запрос | ответ |
| --- | --- | --- |
| `POST /api/activate` | JSON с полями `key` и `hwid` | `200` и сессия; `401 invalid_license` при отказе |
| `GET /api/session` | cookie `license_session` | `200 { authenticated: false }` либо действующая сессия |
| `POST /api/logout` | JSON `{}` и cookie | `200 { authenticated: false }` |
| `GET /healthz` | без авторизации | проверка доступности процесса |

успешная активация и запрос активной сессии возвращают:

```ts
type ActiveSession = {
  authenticated: true;
  license: {
    id: string;
    expiresAt: string;        // ISO 8601
    sessionExpiresAt: string; // ISO 8601
  };
};
```

коды ошибок: `400 invalid_request`, `401 invalid_license`, `403 forbidden_origin`, `413 payload_too_large`, `415 unsupported_media_type`, `429 too_many_requests`, `500 internal_error`. ответы `/api` не кэшируются. запрос с заголовком `Origin` должен точно соответствовать `PUBLIC_ORIGIN`; нативный клиент может не отправлять `Origin`.

## конфигурация и размещение

| переменная | назначение |
| --- | --- |
| `LICENSE_HASH_SECRET` | 32 случайных байта в виде 64 hex-символов; создаётся `configure` |
| `LICENSE_DB` | путь к SQLite; по умолчанию `./data/licenses.sqlite` относительно каталога запуска |
| `PUBLIC_ORIGIN` | точный публичный origin; локально `http://127.0.0.1:3000` |
| `HOST`, `PORT` | адрес прослушивания; по умолчанию `127.0.0.1:3000` |
| `TRUST_PROXY` | пусто/`false` либо `loopback` для локального reverse proxy |

для рабочего домена задайте `PUBLIC_ORIGIN` с `https://` без пути, логина, query и fragment. HTTP допускается только на loopback. TLS завершается на reverse proxy; `Secure` cookie включается для HTTPS origin. не выставляйте незашифрованный Express-порт наружу. при проксировании с той же машины включите `TRUST_PROXY=loopback`, чтобы лимитирование использовало адрес клиента. прокси должен корректно задавать `X-Forwarded-For`; цепочки с удалённым прокси этой конфигурацией не поддерживаются.

managed Preview запускается отдельно в dev-режиме с `PUBLIC_ORIGIN=http://localhost:3000`: его шлюз переписывает `Origin` на этот адрес. это не конфигурация рабочего HTTPS-сервиса; флаг `Secure` cookie в таком Preview не выставляется. обычный `npm start` использует ваш `.env` без этого переопределения.

сохраняйте `LICENSE_HASH_SECRET` вместе с резервной копией базы: смена секрета делает существующие HMAC несопоставимыми и лишает старые ключи работоспособности. не меняйте его при каждом запуске. база использует WAL; делайте согласованную резервную копию или останавливайте сервис перед копированием. на POSIX файлы базы и `.env` создаются с доступом только владельцу; на Windows настройте соответствующие NTFS ACL для сервисной учётной записи.

эта реализация рассчитана на один экземпляр сервиса и локальный диск. лимиты — 10 активаций и 60 API-запросов в минуту на IP, счётчики находятся в памяти процесса. для нескольких экземпляров нужны общая транзакционная база и общий rate-limit store; они не реализованы. `node:sqlite` в Node.js 24 имеет статус Release Candidate, поэтому runtime ограничен веткой 24.x.

проверка переданного HWID — привязка лицензии, не аппаратная аттестация. модифицированный клиент может передать чужое значение; серверное разрешение нужно проверять там, где выполняется защищённое действие, а не только скрывать элементы UI. интеграция с каким-либо нативным приложением в этот модуль не входит.

## проверка

```sh
npm run check
npm audit --omit=dev
```

тесты используют временные базы и синтетические ключи; рабочую базу не изменяют. отдельно проверьте свой HTTPS-домен, reverse proxy, резервное копирование и правила обслуживания лицензий перед развёртыванием.

справочники: [Node.js 24 SQLite](https://nodejs.org/docs/latest-v24.x/api/sqlite.html), [Express production security](https://expressjs.com/en/advanced/best-practice-security.html).
